# Contributing

Thanks for helping improve OpenSignage Studio.

1. Search existing issues first. For bugs, provide WordPress/PHP/WooCommerce versions, exact reproduction steps, and redacted error logs.
2. Fork the repository and create a feature branch; keep changes focused.
3. Run `bash scripts/validate.sh` before sending a pull request. Test with a staging WordPress environment.
4. Open a pull request using the template. Describe user-facing behavior, security impact, and how you tested it.
5. Avoid committing credentials, bot tokens, private control links, real phone numbers, customer names, addresses, business exports, or database dumps.
6. Keep user-visible interface strings in English and prefer accessible HTML controls.

All contributions must be licensed under GPL-2.0-or-later and must not include unlicensed assets.
